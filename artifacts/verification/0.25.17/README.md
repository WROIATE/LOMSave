# 0.25.17 骰子指定结果与单挑直接胜利整合

日期：2026-10-25。游戏：release_1.0.6000.5，Unity 2020.3.49f1。

## 实现

- 两项功能独立实现并编译进 LOMSaveProbe.dll，不分发或调用 ScriptTrainer。
- 骰子在等待“启动”时短按目标项指定结果，仍走原生 ExecuteRoll 的等待、清理和现有结果记录流程；仅替换本次 Roll，不抽随机数、不扣命运点。每个对话实例独立保存一次性请求，重复点击、关闭、读档及下次使用不会沿用上次请求。中键/长按预览和短按选择共用现有输入组件，预览触发后不选择。
- 单挑在原生菜单打开时同步创建“直接胜利”，复用投降按钮样式、重新绑定点击事件。停止当前战斗协程，调用原生 GameOver(true) 处理胜利旗标、条件结果与剧情续接，不自行发奖；同一场决斗只允许一次结算。
- 无新增每帧场景扫描、资源遍历或快照。原插件存在时保留兼容判断，避免同时接管同一个入口。

## 实机验证

启动日志确认只加载 LOMSave Probe 0.25.17；ScriptTrainer.dll 与其配置已从游戏目录删除，恢复备份保留在仓库忽略的 artifacts/backup 下。

1. 读取原有单挑自动档：赵活对南宫家丁。原生菜单中显示一个“直接胜利”，点击后原生胜利结果执行一次，通用决斗成败 C00000 为 1，返回剧情 ch2_2_6_4，南宫浅说“赵大哥，你赢了！”。银两仍为 18222。
2. 在该对白处 F9 打开增强面板，属性和旗标正常显示；Esc 关闭后恢复对白。日志记录内置 debug_shortcut_opened / closed，未依赖外部修改器。
3. 使用此前备份的原故障骰子档（ch2_2_5_4，Point 46）测试：F8 直接恢复成功，校验差异为 0，历史语句执行数为 0。
4. 中键点击第二项只打开影响预览，没有触发骰子选择。关闭后短按第三项，日志记录 selection=3，直接进入飞天弟子讨论宴席中女子的对应对白。
5. 在完整对白处保存到原本为空的 004 测试槽，再读回：准确回到同一句对白（Point 926），校验差异为 0，历史语句执行数为 0，恢复遮罩约 1.362 秒。
6. 再按 F8 回到投骰前，短按第一项：日志记录 selection=1，进入峨眉弟子“够了，够了，越说越不成体统了。”，没有残留上次第三项选择。

三次自由档恢复校验差异均为 0。单挑胜利请求与两次骰子指定请求均有正式运行日志，没有 failed / mismatch 事件。长按沿用既有预览机制与防误选判断，本轮实机输入覆盖短按和中键，未使用自动化模拟长按。
