# 0.22.5 读档黑屏修复

验证日期：2026-10-19，Asia/Shanghai。
环境：游戏 release_1.0.6000.4、Unity 2020.3.49f1、BepInEx 6 Mono Windows x64；同时安装内置修改器 1.1.2。

## 已复现原因

旧版日志中，02:40:15 读取 001 存档后，先设置待恢复脚本 `travel_result_601_501`，随后被改为 `ch6_3_1`。存档目标是赶路事件的第 21 个命令（两个选项），但实际执行了章节开头，目标重放没有启动，恢复遮罩和输入阻断持续存在。

原生 `LoadSlotPanel.OnTitleClick` 在 `LoadGameData` 之后调用 `MissionManagerData.UpdateCheckMissions`。后者会重新选择主线脚本并可能推进主线节点，与 MOD 精确恢复冲突。另外，失焦时原有超时计时会不断延期。

## 改动

- 精确读档及画面恢复期间，暂缓 `UpdateCheckMissions`，保留存档的脚本和任务状态；正常游玩时仍执行原有任务检查。
- Lua 启动脚本若意外偏离待恢复目标，立即停止该次执行并走原有“本段开头”恢复路径，避免在黑色遮罩下运行错误章节。
- 保留 30 秒无进展保护，另加 120 秒恢复总上限；切后台不能无限延长遮罩。
- 兼容检查额外核对每个 Harmony 类是否实际注册，避免仅验证目标方法存在而漏挂拦截。
