# 0.25.18 冷启动建筑事件预览验证

日期：2026-10-25。游戏：release_1.0.6000.5，Unity 2020.3.49f1。正式发布包含此前未发版的 0.25.16 商店恢复修复和 0.25.17 独立骰子/单挑功能，其实机记录分别保留在相邻目录。

## 原因与修复

此前只把后备事件索引接入日期提示和日历。冷启动直接读取养成档时，Story 场景尚未建立 CheckPointManager，建筑预览读取原生 PositionConfig 为空即返回，因而错误提示“进入一次剧情后即可查看”。本轮接通建筑及行动预览、条件说明、单次指定和固定选择，保留原生配置优先和原生执行前实时核验。

后备条目只保存事件池/事件代码，执行时解析当前原生事件对象和 ResultType；不会创建游戏对象、运行 Lua、抽随机数或按事件代码后缀猜测结果。导出的索引增加原生映射 Value 对应的准确脚本名和来源指纹，用于只读效果扫描。索引准备期间已打开的建筑面板会在完成后刷新。

## 实机结果

1. 从全新进程直接读取 003 原生养成档，未先进入剧情。日志确认版本 0.25.18，只有本 MOD，ScriptTrainer 已移除。
2. 大门中键预览得到 8 个事件，默认隐藏 3 个不可触发项；未知条件保持“待判定”，不开放指定。日志明确记录 checkpointManagerPresent=false，旧的“进入剧情”提示消失。
3. 冷启动界面把“馬富貴 买飲料”设为固定选择，显示“已固定”，原有偏好可正常替换。查看条件显示实时旗标值、事件代码 Door_02_E_06 及事件池 Door_02。
4. 关闭预览并出门，日志 next_event_applied 精确得到 Door_02_E_06 → door_02_506，实际进入李富贵在饮子摊前犹豫的对白，与所选事件一致。没有 failed / mismatch 事件。
5. 本轮测试后正常退出，还原备份：111 个存档及附属文件、8 个配置全部哈希一致，无额外测试存档；玩家原固定偏好已恢复，ScriptTrainer 保持删除。游戏未继续运行测试剧情。

## 性能、回归与范围

- 索引首次后台解析及版本/指纹验证约 627ms。首次打开大门的按需事件扫描约 130ms，界面生成约 8.8ms；固定选择/条件展开时界面重绘约 4.4ms。这是本机单次观测，不代表所有建筑或机器。
- 不增加关闭界面时的事件扫描；面板打开时只检查索引准备状态及版本号变化，完成后刷新一次。实时事件条件仍读取当前数值。
- 27 组回归通过；新增冷启动路由覆盖后事件选择共 56 项断言，包含跨事件池不误消费、精确 ResultType、固定跨载入保留、过期拒绝和数据准备提示。索引专项追加两项检查后共 6435 项断言，防止缺失脚本或把龙之反省错误映射到 003。
- 游戏接口检查通过：482 个原生引用、186 个 Harmony 目标、90 项反射成员、28 个补丁类。
- 本轮实机覆盖冷启动大门预览、条件和固定事件实际触发；单次指定、多个行动页签及失效条件由回归覆盖，未声称逐一实测全部建筑/剧情。存读档、独立骰子和单挑的实机验证见 0.25.16 / 0.25.17。
