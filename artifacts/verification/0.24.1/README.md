# 0.24.1 剧情重放性能优化

日期：2026-10-19。环境同 0.24.0：游戏 release_1.0.6000.4、Unity 2020.3.49f1、BepInEx 6 Mono Windows x64、ScriptTrainer 1.1.2。

## 改动

完整路线从原生剧情入口执行，本来就会按实际分支加载角色。取消此路径对整份脚本所有角色的预加载，避免加载未走到的分支、重复执行加载请求。没有完整路线的旧档和回退入口仍保留角色补全。

仅在读档重放的 Lua 调用内，对原生角色字典已存在且有效的角色返回已完成结果。原生 `LoadCharacterAsset` 在此条件下原本也是直接结束，但仍会经 `RunUnityCoroutine` 创建空 Task、再由 `runwait` 等待，产生额外帧交接；原生桥接与 `runwait` 均支持 null，故可省去这段等待。未缓存角色仍完整等待原生异步初始化，其他 C# 调用及正常游玩保留原生行为。

保留对白之间的一帧更新、原生动画、场景等待、路线校验及异常回退，没有提高全局重放倍率。不会通过去掉动画更新而重新引入少人物的问题。

新增按脚本汇总的加载次数、缓存跳过次数、角色加载协程耗时和 Lua Resume CPU 耗时。每次角色加载仅在内存累计数据，不逐条写日志；脚本切换和恢复到目标时输出一次汇总。过期代次的加载仍停止并释放。

## 实机对比

使用 0.24.0 测试时留存的同一新格式跨脚本分支：`ch6_10_1` → 骰子 → `ch6_10_1_part_2` 第 58 条选择。完整路线包含 2 个脚本、40 条判定、1 次骰子结果，跳过 158 句对白。

基线日志 `LOMSaveProbe-20261019-111153.jsonl`；最终版日志 `LOMSaveProbe-20261019-121403.jsonl`。总时间从 `load_argument` 到遮罩解除，包含读档准备、场景、重放、状态校验和最后画面恢复。冷启动指重新启动游戏进程，未清空操作系统文件缓存。

| 操作 / 阶段 | 0.24.0 | 0.24.1 |
| --- | ---: | ---: |
| 冷启动：前半段及脚本跳转 | 4.439 秒 | 3.697 秒 |
| 冷启动：完整读档 | 7.380 秒 | 6.468 秒 |
| F8 连读：前半段及脚本跳转 | 3.910 秒 | 3.119 秒 |
| F8 连读：完整读档 | 6.102 秒 | 5.092 秒 |

这个样例的前半段减少约 17%～20%，完整读档减少约 12%～17%。属于同一台机器、同一存档的样例对比，不代表所有剧情都有相同比例的收益。

最终版冷读的前段实际加载 18 次，省去 40 次已缓存请求；续接段实际加载 5 次，省去 9 次已缓存请求。前段角色加载协程累计约 1.31 秒，Lua Resume CPU 累计约 0.21 秒。连读对应约 1.28 秒和 0.17 秒。角色协程耗时包含异步初始化及等待，不等于纯磁盘 I/O；Lua CPU 也不包括独立 Unity 资源协程全部工作，不能把总时间简单相减后认定剩余全是动画。

最终版冷读与 F8 连读的覆盖前路线校验、最终状态校验均为 0 差异，未中止或超时；选择、背景及人物与 0.24.0 正常推进的截图一致。

再次 F8 连读为 5.055 秒，前段 3.113 秒；读取原 005 旧格式骰子档为 2.905 秒，正确回到“县主的混乱暴言”投骰前。最终版共 4 次读取全部通过最终状态校验，3 次新格式读取的覆盖前校验也均通过，无异常、中止、超时或立绘恢复失败。
