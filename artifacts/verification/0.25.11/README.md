# 0.25.11 死亡页按钮同步显示

读取游戏按钮由死亡演出结束后创建，改为在 GameOverController.Awake 中提前创建。原生“回主选单”与新增“读取游戏”共用一个全屏 CanvasGroup，交给原生 Start 协程统一淡入并开启输入，不增加逐帧同步或资源扫描。

验证结果：

- 编译通过；465 个原生引用、164 个 Harmony 目标、60 个反射成员检查通过，24 个补丁类注册。
- 实机读取原有战斗自动档，经原生投降进入“砍死”页面；日志在 GameOver 场景切换完成前记录 death_load_button_added，sharedReveal 为 true。
- 两个按钮字体、尺寸及右对齐保持原生样式，共用原生淡入和输入控制。截图为演出结束后的最终状态，未进行逐帧录像测量。
- 点击打开完整读档列表，Esc 返回死亡页，再次打开正常；从死亡页读取手动 003 成功，回到四月中旬养成地图，贡献 63、心相 100、剩余行动 1、银两 18590。
- 实机测试期间 Player.log 中 Exception / Error 为 0。
- 测试前将用户当前进度存入原本空闲的手动 003，正常退出后备份 111 个存档文件和 9 个配置。测试后归档并还原 5 个由战斗自动保存和死亡计数修改的文件，111 个存档及 9 个配置哈希与本次基线全部一致，003 新进度保留。
- 清理测试数据后启动曾未及时暴露游戏窗口，工具未获准控制 Steam，未对 Steam 执行输入。最终只读检查发现新 Mortal 进程已经进入阎关二煞战斗，有新的自动保存及死亡计数变化，故停止所有游戏输入和基线还原，保留后续游玩状态。手动 003 仍保留。111 个存档和 9 个配置全部一致的校验时间点是前述清理完成时，后续游玩写入不属于测试数据。
