# 0.23.2 续接剧情读档角色缺失（历史候选，已由 0.24.0 取代）

以下记录保留候选完成时的状态。后续在 Unity 实测发现，补齐角色对象后还缺少动态角色的默认立绘初始化，单独使用本候选仍会失败；完整修正与恢复流程重构见 `../0.24.0/README.md`。本候选未独立发布。

日期：2026-10-19，Asia/Shanghai。环境为 `release_1.0.6000.4`、Unity 2020.3.49f1，当前游戏已加载 0.23.1。

## 现场与原因

18:24:23 读取“最近分支”，目标为 `ch6_10_1_part_2` 第 58 条 `choose`，即收容孟仙谣前的选择。日志显示场景切换、目标配置及 Lua 初始化完成；选项分析已命中缓存，耗时约 0.025 ms。随后 `Player.log` 报“角色 Key player 不存在”，`Fungus.PortraitController.CleanPortraitOptions` 在 0x3b 处因 `options.character` 为空抛异常，Lua 协程退出。

该脚本开头为其他人物显式调用 `LoadCharacterAsset`，但主角直接执行 `stage.show{character=characters.Get("player"), ...}`，沿用了上一段剧情的角色上下文。精确读档直接从续接脚本恢复，而新 Story 场景的角色注册表为空，因此在第一条对白之前中断。

18:25:45 原有超时机制触发并移除恢复遮罩、重载该段开头；回退仍缺少角色上下文，再次停在同一处。不是本次事件预览去重或剧情分析耗时造成的加载等待。

已只读备份当前分支存档及附加记录、现场 Player.log 至忽略目录 `artifacts/backup/black-screen-0.23.2-20261019/`；未改写用户存档、关闭或操作游戏窗口。

## 改动

- 只在精确恢复的当前剧情 Lua chunk，以及指定的一次失败回退 chunk 中，先等待原生 `LoadCharacterAsset` 加载脚本引用的去重角色，再执行原脚本。该段共引用 9 个角色；不遍历全剧情或存档内历史立绘。原生加载器会复用已注册角色。
- 原脚本作为完整后缀保留，不增加对白、选择、骰子或属性命令，不修改检查点顺序、随机结果与剧情数值。正常游玩和临时追踪脚本不增加这段加载。
- 仅包装与当前剧情匹配的 Lua 协程；恢复期间异常或未到检查点就结束时，记录原因并立即调用已有回退机制。达到检查点后的正常结束和异常仍沿用原行为。
