# 0.25.3 事件预览页签与名称

在游戏 `release_1.0.6000.5` 完成实机验证，最终 DLL 已覆盖游戏目录。21 组回归、42 项事件预览断言及游戏接口检查通过。

## 改动

- 建筑事件按外层行动分成页签，后山使用游戏原生名称“挑柴”“修练”；待触发人物剧情使用独立页签。
- 行动名称按游戏的本地化规则解析，不再直接展示复合参数编码。通用事件标题去掉 `P_` 与内部序号格式，保留可区分不同事件的变体编号；原始事件与事件池代码仍可在条件中查看。
- 嵌套选项归入所属行动，同一页签内去重；不同原生事件池保留各自的指定范围，避免把名称相同的事件误当成同一事件。
- 页签各自保留滚动位置及不可触发事件的显示状态。切换仅重建界面，不重新扫描 Lua 或计算事件权重；同一原生池的分析结果在一次预览内复用。
- 保持原有黑金配色、单次指定与固定选择逻辑。

## 验证

- 后山原生菜单与预览名称一致，挑柴与修练分别展示；修练的两组原生事件池分别显示。
- 炼丹房两个外层行动独立展示，嵌套“我是来工作的。”事件不在同一页重复列出。分别滚动、切换和展开不可触发项，状态互不影响。
- 固定炼丹成功事件后重启，固定标记仍在；实际执行炼丹触发 `Alchemy_Work_S_01`，出现“做出了超乎预期的惊艳成果”剧情，日志仅记录一次指定应用。
- 21 组回归通过，事件预览有 42 项断言。原生接口检查解析通过 449 个引用、145 个 Harmony 目标、49 个反射成员及 21 个补丁类。待触发人物剧情的页签归类由回归覆盖，本轮未另造实机待触发剧情存档。
- 本机日志中，炼丹房扫描约 29～37 毫秒、后山约 76～83 毫秒，页签界面构建约 5.5～12 毫秒。这些是对应方法耗时，不代表完整帧耗时；切换页签未出现新的扫描记录。
- 测试结束正常退出游戏，183 个存档文件和 5 个配置文件还原后，共 188 个 SHA256 校验一致；游戏目录保留新版 DLL。
