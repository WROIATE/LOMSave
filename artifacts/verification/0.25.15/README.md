# 0.25.15 投骰前手动存档修正

修正 0.25.14 把整个骰子界面一律禁用的错误。普通选项和等待点击“启动”的投骰前界面均允许自由存档；启动后、转动中和结果确认阶段禁用，在按钮旁显示一处小字原因。原生允许存档的位置仍使用原生权限和存读档流程。

DLL SHA256：`4a28f9117ab3759f1458e4c9507874ae9869caaaf0210a7386a95bcfe58c3a99`

## 自动验证

- 26 组回归通过；存档可用性 154 项断言，包含全部 64 种骰子界面状态组合。点击启动后，即使启动按钮尚未隐藏，也不可保存。
- 新式 `ExecuteRoll` 与旧式 `choosetimer` 续接均测试了投前保存、恢复骰子配置与局部变量、不重放历史语句、不额外消耗随机数，以及继续后属性、金钱、命运点只结算一次。
- 473 处原生引用、174 个补丁目标、87 处反射成员和 25 个补丁类通过兼容检查。
- 可用性刷新继续按 80ms 节流，只读取当前控件与演出状态，不生成快照、扫描资源或读写文件；实际保存时重新检查。

- 开场“招募弟子结果”投骰前，“启动”可见、尚未投骰，保存按钮可用，见 [截图](dice-before-save-enabled.jpg)。在原空白 002 槽保存，再读取，仍回到同一投骰前等待界面，见 [截图](dice-before-restored.jpg)。
- 直接恢复目标为 `ch1_1` 第 653 点、类型 `dice`；状态校验差异为 0，历史语句执行数为 0，首次手动读回遮罩约 1.17 秒。
- 点击启动后得到 81 点；结果尚未确认时保存按钮置灰并显示原因，见 [截图](dice-after-roll-disabled.jpg)。该截图是结果确认阶段，不是尚未投骰或正在转动。随后从结果页再次读回 002，重新停在启动前，校验差异为 0，恢复约 1.13 秒；贡献 30、心相 50、行动 4、银两 23000。
- 普通“附和三师兄／唯唯诺诺”选项页仍可进入储存页面，按钮没有锁和禁用提示，见 [截图](choice-save-enabled.jpg)。普通选项的实际保存、读回与选择已在 0.25.14 验证，本次复查入口未受影响。
- 当前游戏实测的是新式骰子；旧式骰子通过原生接口与 Lua 续接回归验证。转动瞬间未单独截取暂停截图，启动标志的禁用由状态组合测试覆盖。

测试文件已归档，原有 107 个存档及附属文件、9 个配置文件均按备份哈希恢复，无额外测试文件。启动时 Steam 回填的测试文件也已归档。游戏回到原来的选项和数值，见 [原进度截图](user-progress-restored.jpg)。候选、分发目录与游戏内 DLL 哈希一致。本地游戏已覆盖同一 DLL；正式发行内容与更新记录见根目录 [CHANGELOG.md](../../../CHANGELOG.md)。
