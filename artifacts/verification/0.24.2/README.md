# 0.24.2 功能复核与剧情入口修复

## 发现及修复

1. **寺庙存档读回酒楼：已确认。** 从旧格式档继续游玩后，原生游戏在同一个 LuaManager 中开启了新的剧情入口，但 MOD 仍沿用酒楼的入口状态。寺庙菜单因此缺少一个选项，严格校验失败后又回退到酒楼。原始 `.dat` 中的寺庙脚本和进度仍在；错误发生在恢复过程。
   - 路线在原生新入口重新建立，无需等待 LuaManager 更换；完整路线的正常续接和同名脚本重入保留历史。
   - 入口状态必须属于实际恢复的脚本。旧格式缺失或错绑入口时使用请求存档的状态，不借用其他剧情的旧旗标。
   - 入口选择同时用于重放、捕获和异常回退。新读档清除上一轮待回退状态；异常回退出现明确提示。
2. **历史骰子重投消耗未恢复：代码与原生 IL 确认。** 原生 `UseFatePoint` 扣除命运点，直接恢复最终骰子选择会跳过这项消耗，导致重放后的状态不一致。
   - 在骰子选择记录中保存实际消耗，重放时恢复一次，并保留到后续存档。
   - 旧记录没有消耗信息时不凭空扣点；新格式严格状态校验仍保留，不能保证修复旧记录已经缺失的信息。
   - 骰子命令被校验拒绝时立即停止，不继续打开原生投骰界面。
3. **附加存档直接覆写：风险修正。** 改为先写临时文件再替换，保留 `.bak`；删除槽位时清理对应临时文件及备份。主存档与附加状态的时间、哈希、脚本绑定继续生效。
4. **旧游戏版本的正常迁移被误判为恢复失败：实机发现并修复。** 一个 `release_1.0.5000.13` 存档已到达正确选项，但原生升级新增的数据与旧文件比较出现 747 处差异，触发了回退。现在在重放前独立调用原生迁移建立校验目标，不从重放结果反推正确答案，也不忽略整组旗标或好感。原始存档不改写；迁移失败仍拒绝恢复。同版本及非剧情重放不额外加载。修复后同一旧档恢复原选项、房间、人物，最终状态 0 差异，遮罩 1.86 秒，迁移 85 毫秒。

## 实机恢复与性能

环境：`release_1.0.6000.4`、Unity `2020.3.49f1`、BepInEx 6 Mono x64，保留用户的 ScriptTrainer。时间为 MOD 恢复遮罩持续时间，包含剧情重放和画面恢复，不是全部磁盘 I/O 耗时。

| 样本 | 结果 | 遮罩时间 |
| --- | --- | --- |
| 原始 009 寺庙故障档 | 寺庙雨夜、完整休憩菜单；最终状态 0 差异 | 冷读 2.94 秒 |
| 最终 DLL 再读原始 009 | 同一寺庙、完整休憩选项，未回到酒楼 | 2.31 秒 |
| 原寺庙分支 F8 连续两次 | 同一寺庙菜单，未回酒楼 | 2.05 / 2.05 秒 |
| ch6_10_4 普通选项 | 返回威吓／好言相劝／唱歌 | 3.20 秒 |
| 骰子逆天后保存再读取 | 同一台词，消耗记录为 1，最终状态 0 差异 | 3.36 秒 |
| 旧档继续→养成→锻造→新档重读 | 3 个脚本访问，覆盖最终状态前的严格比较及最终比较均 0 差异 | 1.32 秒 |

## 离线证据

- 19 组回归、662 项断言通过，包括实际游戏脚本在内嵌 MoonSharp VM 中的 10 项断言。
- 寺庙用例运行当前原生脚本到第一个菜单：过期酒楼旗标可复现缺失第 4 项，使用生产入口选择策略后恢复 `O_6_10_3_Break_01_006`。
- 生产骰子协程与生产命令记录一起测试：正常重投扣点、保存、跳过 UI 重放、再保存、缺失消耗的旧记录，以及命令拒绝后的停止。
- 434 个原生引用、135 个 Harmony 目标、42 个反射成员通过，20 个补丁类注册。
- 用 `tools/Build-Plugin.ps1` 可通过 PowerShell 自带 Roslyn、游戏的 Mono 引用编译，无需独立 SDK。现有 CS1701 引用版本兼容警告保留。

安装 DLL SHA256：`079A682F964D28775505030E2CDB4256052E3A014AF18EC0C507119804F47CBB`。

经用户授权正常退出残留窗口，在退出后新建完整备份，再覆盖 DLL 并启动验证。结束后已正常退出测试游戏，恢复这份最新基线中的 177 个存档文件及 5 个配置文件，逐项 SHA256 比较 0 差异；测试产生的文件已单独归档。自动播放速度通过原生设置页恢复为原值 1.8 倍。游戏目录保留上述最终 DLL。原始故障档与完整日志只在本地忽略目录保留。本轮未推送或发布。
