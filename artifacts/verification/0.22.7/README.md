# 0.22.7 混战直接胜利与襄阳自动存档（待实机验证）

日期：2026-10-19，Asia/Shanghai。当前游戏为 `release_1.0.6000.4`。

## 现象与证据

用户反馈混战暂停页“直接胜利”点击完全没有反应。当前 0.22.6 运行日志在 11:08:27 记录到按钮创建，但没有奖励模拟或结算事件。旧实现复制投降按钮，未同步其交互状态、未加入原生菜单的交互按钮数组，且通过隐藏测试按钮的事件转发胜利。现有日志不足以确认本次无响应发生在禁用状态还是事件调用阶段；本次修复覆盖这两个依赖，并补充点击及结算诊断。

襄阳当前养成菜单的事件为 `event+标题+0+0`，实际通过剧情旗标计数推进，不扣玩家行动次数。旧“最近行动”只覆盖扣行动次数或选项行动消耗大于零的路径，因此遗漏。日志可见原生 `auto_free` 写入，但发生在 `choose` 检查点建立前，附加记录以 `matching_checkpoint_missing` 跳过；这和“完全没有原生自动档”是不同问题。

## 改动

- 暂停页快捷按钮加入原生交互数组，并同步投降按钮的交互状态；打开读取／设置子页面时一起禁用，返回时一起恢复。准备页与暂停页统一直接调用原生胜利流程，解除暂停后由游戏发放表现、属性、点数和拾取金钱奖励，保留单次结算保护。
- 新增 `team_battle_skip_requested`、`team_battle_skip_settled` 事件；按钮配置日志记录实际 `interactable`，便于区分点击未送达、被保护条件拦截和原生结算已开始。
- 通过原生 `LuaManager.AutoFreeSave` 识别养成剧情菜单，在其第一个匹配选项检查点补写 `auto_free`，为原生养成自动档建立精确选项记录；每次菜单只补写一次，不按地图 ID 写例外。
- 该菜单中行动消耗和贡献消耗均为零的 `event` 选项，在回调执行前保存 `auto_action`。退出、商店、仅消耗贡献、隐藏／禁用项目和普通免费剧情选择不纳入这项补充。新脚本会清除菜单上下文，所有重放阶段仍禁止写入。

## 验证

- `tests/Test-All.ps1`：16 组、474 项断言通过。
- 新增 10 项生产混战挂钩断言：按钮启停、子页面交互同步、隐藏测试按钮没有监听器时仍结算、解除暂停、保留原生奖励与已有拾钱、防止重复结算、准备页快捷结束。
- 自动存档策略新增 6 项断言；另有 15 项生产存档挂钩断言，驱动脚本初始化、原生养成存档、选项创建和点击顺序，检查选项检查点、只补写一次、保存先于旗标变化、零消耗排除规则、重放抑制、上下文重置、正消耗路径及未提交写入的诊断。
- `tools/Test-PluginCompatibility.ps1`：413 个原生引用、124 个 Harmony 目标、35 个反射成员通过，18 个补丁类均注册。检查对象为当前游戏 DLL；测试桩不等同于 Unity 实机验证。
- `Build-Local.ps1`：编译通过，只有既有的 CS1701 引用兼容警告。
- 构建 SHA256：`721C105FD46D6E290A315F026F6073AB95873469E604B48338453647A1A7B0E9`。
