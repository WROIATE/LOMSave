# 0.25.1 人物清理导致黑屏：调查与验证

状态：已覆盖安装 0.25.1，通过离线回归、两轮原路线实机复测和正式插件冷启动直接续接检查；用户退出时的存档与配置已恢复。

环境：`release_1.0.6000.4`、Unity `2020.3.49f1`、BepInEx 6 Mono x64、ScriptTrainer 1.1.2。安装与交付 DLL SHA256：`109BAFC74D4CFB300D930FFA4073DD634A3E40DB5B7845481D79127B9FF002A6`。

## 复现

用户两次复现：读取旧格式“最近分支”→继续进入养成地图→出门→左 Ctrl 快进→崆峒众人与赵活的对话结束后一直黑屏。最后一句为“我明白了，多谢道长指点迷津”，位于 `S0801_02_02`。

00:32 和 00:50 的最近分支读取分别约 20.91、20.06 秒，均为第 11 版记录的历史兼容恢复，经过 17 次脚本访问。读取已经完成、业务状态校验零差异；它与随后出门时的黑屏不是同一次加载。

黑屏前脚本先淡出，再统一隐藏人物。小梅分支没有出场的郁竹也在清理列表中。原生 `StoryStageController.Hide` 对空人物直接返回；`HideMood` 则假定已经出场的人物具有表情面板。

0.25.0 的续接编译器在每条 `characters.Get(...)` 前都补充资源加载，也作用于普通游玩及清理语句。结果把本应保持不存在的郁竹加载成一个尚未出场的人物。原生表情面板在出场时创建，单纯加载并不会创建；随后原生退场函数访问空面板抛出异常，剧情协程终止，画面停在已经淡出的状态。

## 修复

- 普通剧情只增加存档检查点，保留原生人物加载行为。
- 只有直接续接和缺少历史上下文的兼容恢复，才按需补充继承人物。
- 人物隐藏属于清理操作，不触发人物补载；保留原生“人物不存在则忽略”的行为。
- 兼容恢复的资源上下文不再因最终脚本编译覆盖而丢失。
- 不增加逐帧场景扫描，不吞掉原生异常，也不重跑已经结算的剧情。

## 离线验证

使用游戏自带 MoonSharp Lua 引擎建立人物生命周期测试：加载人物不会创建表情面板，出场才会创建，隐藏不存在的人物直接返回，隐藏已加载但未出场的人物报错。原始代码通过，0.25.0 的编译结果稳定报 `HideMood` 同类错误；修复后的普通编译、兼容恢复、直接续接均通过。直接续接仍会加载后续真正需要展示的继承人物。

20 组回归通过。2068 份脚本、77717 个续接点编译检查通过，零失败，41.25 秒。游戏接口检查通过：447 个原生引用、145 个 Harmony 目标、49 个反射成员、21 个补丁类。

## 实机验证结果

2026-10-20 00:58 正常退出用户许可关闭的黑屏窗口，刷新退出后的备份，覆盖插件。原版本备份、测试进度及完整诊断日志保存在本地备份目录。

键盘自动化无法维持左 Ctrl 按下，因此两轮快进使用临时独立测试插件调用 Ctrl 对应的原生 `StoryManager.SkipDialog`，并仅观察退场参数。它没有改变人物加载或退场结果；并非物理长按键盘测试。辅助插件已移出游戏插件目录，冷启动续接检查仅加载正式插件及原有 ScriptTrainer。

测试期间没有发生原剧情黑屏异常。正常退出时，原生 `FlowchartPlaceholder.OnDestroy` 记录了一次退出清理空引用，与已完成的剧情续接不同；保留在完整日志中，没有将其计入剧情执行无异常的结论。

20 组回归、脚本批量编译不代替所有分支的完整游玩。本轮集中验证此次黑屏及存读档续接；事件固定与事件预览未在 0.25.1 重测，最近一次实机证据见 `../0.25.0/`。

测试结束后正常退出游戏，归档测试存档并恢复验证前的 183 份存档文件、5 份配置；188 个 SHA256 全部一致，零差异。正式插件保留 0.25.1，测试辅助已移除。
