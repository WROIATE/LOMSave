# 0.22.4 事件单次指定修复

## 问题与证据

2026-10-18 的本机日志显示，“龙之反省”（`Door_02_E_03`）可选且权重为 30。

- 19:49:39 指定后，进入大门先触发已就绪的 `S0026_01`。
- 19:51:28 再次指定后，进入普通大门脚本，实际随机到 `door_02_505`，没有指定事件生效的日志。
- 19:53:22、19:54:00 指定后，均先触发已就绪的 `S0025_01`。

原生 `PositionController.OnPositionClick` 的顺序为主线、人物任务、普通行动。MOD 保留此顺序，页面增加优先级说明。

真正的指定丢失来自 `UseSelectedMission`：随机事件的 `Mission` 为 null，未找到指定人物任务时 `data` 也为 null，原判断将两者视为匹配并清空 `_pending`。修复为先确认人物任务有效且仍处于就绪列表，再消费对应的人物任务指定。选择日志同时记录事件池与稳定编号。
