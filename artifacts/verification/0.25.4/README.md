# 0.25.4 剧情日历与日期提示

在 `release_1.0.6000.5` 完成实机验证。最终 DLL 已安装，测试前 183 个存档和 5 个配置文件已还原，共 188 个 SHA256 校验一致。未推送仓库或更新线上 Release。

## 行为

- 日期右侧有剧情时显示 `◆ 数量`，点击与 F10 均默认打开当前剧情汇总。
- 汇总列出主线、原生已就绪人物剧情、当前条件满足的特殊事件，以及地点和行动路径。普通工作正常、成功、失败等结果不列入。
- 已就绪剧情标注“进入即触发”，工作中的随机剧情标注“可能遇到”。同一命名脚本的多个入口合并路径；不同脚本即使同名也不合并。
- 全年总览的今日格显示剧情数量，点击今日可在行动记录上方查看清单。保留原有手动备注、自动行动记录与跨周目备注提示。
- 复用游戏任务的就绪结果和优先级。特殊事件只读检查条件，不调用原生 Execute、Lua、GetResult，不推进任务、不修改数值或消耗随机数。无法确认的路径不冒充可触发路径。
- 缓存静态脚本与菜单路径；状态变化后延迟合并刷新，稳定养成界面每帧最多处理一个建筑，空闲帧不重新分析事件。读档、换旬和剧情恢复期间隔离旧快照。

## 验证

- 日期图标位置与点击生效，F10 开关正常；全年总览和日期详情中的数量与清单一致。截图：[图标](date-indicator.jpg)、[默认汇总](current-events.jpg)、[全年表格](year-overview.jpg)、[日期详情](date-detail.jpg)。
- 原生养成自动档的四年二月下旬，显示出门、后山的“决战前下山”。点击后山实际进入 `S0802_01` 并展示该剧情选项，和提示一致。[实际触发截图](ready-story-applied.jpg)。这两个入口实际使用 `S0801_01`、`S0802_01` 两个不同脚本，因此保留两条。
- 读取手动档 25 的一年五月上旬，旧日期的就绪剧情已清除，显示“后山 · 挑柴 → 登崖眺望”“后山 · 修练 → 烤鱼”，没有普通工作结果。
- 连续浏览汇总、全年总览与日期详情期间，没有新的事件扫描记录，未重复执行剧情。
- 最终 22 组回归通过，其中 38 项剧情日历断言覆盖实际菜单脚本、嵌套路径、不可用选项、主线拦截、行动不足、重复入口合并、跨日期与读档隔离、静态缓存及空闲帧不扫描。主线拦截由离线测试覆盖，本轮未另造实机主线存档。
- 接口检查通过：453 个原生引用、158 个 Harmony 目标、49 个反射成员、22 个补丁类。
- 本机首次有数据的扫描中，单个建筑约 0.02～22.2 毫秒，分别分布在不同帧；这是方法耗时，不是完整帧时间或读档耗时。空闲时不持续扫描。

## 已知边界

冷启动直接读取养成档时，原生特殊事件配置尚未随 Story 场景加载。主线和已就绪任务立即显示，页面明确提示“特殊事件数据尚未加载；进入一次剧情后自动补全”。[冷启动截图](cold-free-summary.jpg)。没有为了提示额外加载剧情场景，以免改变游戏状态或增加场景加载成本。

汇总仅反映当前日期、当前存档；不根据当前属性倒推历史或预测未来。随机事件按当前数值筛选，后续选项或行动中的数值变化仍可能改变结果。
